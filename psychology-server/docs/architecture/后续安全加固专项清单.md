# 后续安全加固专项清单（P1-16）

> 对应文档：《AI 心探探多模态数据采集平台总体架构设计说明书 **v1.3**》§17.2、§17.5、§19.3 P1-16、§22 D12
> 日期：2026-11-17
> 性质：**后续独立专项的排期与验收依据。本次只出清单，不执行任何改造。**
> 启动条件：P0 业务功能开发与端到端联调完成且稳定（阶段 1–10 验收通过），由项目负责人另行确认启动日与排期。
> **核心声明**：P0 期间暂用 HTTP 属阶段性安排，**不代表取消安全要求**。本专项不做，S1（全链路明文）与 S2（token 明文传输）风险将持续存在。

## 0. 专项边界

### 0.1 本专项要解决的问题

| 编号 | 风险 | P0 现状 | 专项目标 |
| --- | --- | --- | --- |
| S1 | 全链路明文 HTTP，登录 token、作答文本、转写文本可被公网中间人读取 | 存在 | 公网仅 HTTPS，关闭明文入口 |
| S2 | 设备 token / App token 明文传输与明文存储 | 存在 | 传输加密 + 存储哈希化 |
| S3 | 设备系统时间未对时，无法校验证书有效期，也无法作为可信时间参考 | 存在 | 设备接入可信时间源 + 服务端时间质量校验 |
| S4 | 旧固件硬编码 `http://…:8000`，App 无最低版本阻断 | 存在 | 受限过渡 + 明确关闭条件 |
| S5 | 请求可被重放、可被伪造来源 | 存在 | 签名/防重放（P2 可选项，见 §0.3） |

### 0.2 明确不在本专项内（避免范围膨胀）

- 不改业务数据模型与接口语义（除必要的传输层与鉴权头）；
- 不做硬件安全元件、mTLS、设备证书烧录（P2）；
- 不引入 WAF、SIEM、堡垒机等企业级安全设施；
- 不重构 P0 已验收的业务逻辑。

### 0.3 阶段归属

| 阶段 | 内容 |
| --- | --- |
| **P1-16（本专项）** | SS-01…SS-20：域名证书、Nginx/443、双端 HTTPS、设备校时、证书校验、token 哈希、旧端收敛、安全验收 |
| **P2（预留）** | SS-21…SS-24：mTLS / 请求签名 / 硬件身份 / 导出二次授权 |

## 3. 过渡期与倒计时规则

1. **起算日 = 安全专项上线日（T0）**，不是文档日期，也不是 P0 结束日；当前**不计时**。
2. 过渡期建议 **90 天**；关闭条件满足其一即可：① 在役设备全部升级；② 过渡期到期。
3. T0–T3 四阶段沿用 §17.5.4：
   - T0 准备：证书、Nginx、A 监听调整（不切流量）；
   - T1 新端切换：新固件 + 新 App 走 HTTPS；
   - T2 旧端收敛：旧端流量下降、按设备排查；
   - T3 关闭：关闭公网 8000。
4. 过渡期内发现异常上传或克隆迹象，直接吊销设备 token，不等关闭日。
