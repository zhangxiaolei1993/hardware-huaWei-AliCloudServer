## 2. 逐任务交付定义

### P0-1 会话模型扩展（M1）

- **目标**：`sessions` 支持三值来源、外部会话 ID（N1）、会话类型白名单、4 个时间锚点列、补传截止时间。
- **字段**：`source_system VARCHAR(32) NOT NULL default 'standalone'`、`external_session_id VARCHAR(128) NULL`、`anchor_utc_at`/`anchor_monotonic_ms`/`anchor_source`/`anchor_uncertainty_ms`、`late_upload_deadline DATETIME NULL`。
- **关键约束**：
  - **唯一约束不得含 `external_session_id`**（同一 N1 允许对应多个 S1，见 AC-32/AC-34）；
  - 建会话幂等键为 `(source_system, client_request_id)`；
  - 禁止把 `'unknown'` 等兜底串写入 `external_session_id`（422 `INVALID_EXTERNAL_SESSION_ID`）。
- **完成定义**：老客户端不传新字段仍 201；传 `external_session_id` 能建集成会话；重复建返回 `created:false`（AC-01/AC-02）。

### P0-2 会话类型放开

- **目标**：`session_type` 由 `Literal["emotion"]` 放开为 `emotion` / `multimodal` / `assessment` / `custom`。
- **完成定义**：`emotion` 仍可用；其余三类 201（AC-14）。设备端不读该字段（AD-7），故服务端必须做门控（§6.7 G1）。

### P0-3 过程事件表与接口（M2）

- **目标**：新建 `timeline_events`，提供批量上传与查询；13 类事件；答案类字段禁止入库。
- **完成定义**：批量上传成功；含 `answer_value` → **400 整批拒绝**（AC-06）；事件级幂等生效。

### P0-4 结果快照表与接口（M3）

- **目标**：新建 `external_result_snapshots`，接收客户端转发的 B 端测评结果摘要。
- **硬要求**：
  - 白名单外字段一律拒绝，含 `score_list`、`radar_charts.chart1_phq9_items`（AC-29）；
  - `questionnaire_code` = **客户端 `scale_id` 文本化**（实测 `22`），非 B 返回编码；
  - `result_version` 由**客户端维护**（B 无 `result_id`、无版本字段）；
  - `trust_level` 只能是 `client_relayed`。
- **完成定义**：AC-30（真实样本 + `radar_norm` 有值）、AC-31（同 key 重放 `duplicate`，改内容 409）、AC-36（编码格式校验）。

### P0-5 多批次上传与批次幂等（M4）

- **目标**：解除「一会话一次上传」；新增 `upload_batches`，幂等键 `(session_id, source, client_request_id)`；多批次累加后重算并 **UPDATE 同一行** `emotion_results`。
- **不改**：`emotion_results` 的唯一约束与列（D5 仅针对该表不引入 `result_version`）。
- **完成定义**：同会话分两批上传数据累加；同批次重放 `duplicate:true` 行数不变（AC-04/AC-05a）；历史单批会话行为不变。
- **风险**：需回填历史批次；回填脚本必须先 dry-run。

### P0-6 会话-设备多对多（M5）

- **目标**：新建 `session_devices`，支持一会话绑多设备。
- **完成定义**：重复绑定幂等；按 `device_id` 可区分数据（AC-13）。

### P0-7 时间与质量字段（M6）

- **目标**：`emotion_records` 增加 `device_timestamp` / `monotonic_ms` / `clock_offset_ms` / `frame_index`（全 nullable）、`quality`（NOT NULL default `legacy`）、`quality_info`（JSON）、`protocol_version`，并按 §8.5 推导质量。
- **P0 事实**：设备**不上报** `device_timestamp`/`monotonic_ms`，故 P0 只产出 `legacy` / `missing`，**不产出 `estimated`**。
- **完成定义**：旧固件三字段请求 200 且 `quality=legacy`（AC-16）；缺 `device_timestamp` 为 `missing`（AC-17）；`server_received_at` 绝不参与质量判定（AC-18）；客户端伪造 `quality` 被忽略（AC-21）。

### P0-8 时间校验放宽

- **目标**：`relative_seconds >= -5.0` 合法；上界 `session_elapsed + 600`；超界**只标记 `out_of_range`**，不整批 422。
- **完成定义**：AC-09（`-3` → `pre_anchor` flag）、AC-10（超界 200 + flag）。

### P0-9 受试者脱敏标识（M7）

- **目标**：`subject_ref = HMAC_SHA256(RESEARCH_SALT, source_system + ':' + external_user_id)` 前 16 hex；新增 `external_user_id`。
- **注意**：这是**不可逆脱敏关联标识，不是加密**，不提供任何机密性，不得用于宣称 P0 已做加密改造。
- **完成定义**：不传 `external_user_id` 时回退用 `user_id` 并标记；导出默认不含 `user_id`。

### P0-12 Flutter 结果同步与本地队列

- **目标**：调用 `POST /sessions/{sid}/results`；本地持久化待同步队列；稳定 `idempotency_key = res:{session_id}:{questionnaire_code}:v{result_version}`（S1 作用域；`questionnaire_code` = 客户端 `scale_id` 文本化，服务端逐字校验，不符返回 422 `IDEMPOTENCY_KEY_MALFORMED`）。
- **事实**：FD-7 已核实现状为零（仅 `SharedPreferences`），需从零引入 DB schema + 状态机。
- **完成定义**：A 不可用时结果进本地队列，恢复后补传成功且不重复（AC-08）。

### P0-13 Flutter N1 修正

- **目标**：`external_session_id` 改用答题会话 ID（N1）；N2/N3 拆为独立 `ai_thread_id`；持久化 N1；移除 `unknown` 兜底；结果页入参新增 `externalSessionId`；旧历史无 N1 标 `legacy`。
- **完成定义**：结果与过程事件能挂到同一 `external_session_id`；不出现 `unknown` 写入。

### P0-14 分级兼容接收器

- **目标**：协议版本推断（无 `stream_id` → 1.0）；`quality`/`quality_info` 推导；**默认流补全**；响应头 `X-Protocol-Accepted` / `X-Compat-Warning`；v1 路径冻结、严格 schema 关闭。
- **完成定义**：AC-16~AC-20 全通过；旧固件 200 不被拒；`stream_id` 默认时带 `stream_defaulted` flag 与告警头。

### P0-15 设备身份保护（D3 P0 子集）

- **目标**：注册快照与变更分级（I1–I3）、token 强绑定（I4）、`rotate-token`/`revoke`/`reinstate`（I5/I9）、克隆与异常注册/上传检测（I6–I8）、`device_audit_events` 落库（I10）。
- **P0 不做**：硬件级身份、mTLS（P2）。
- **完成定义**：AC-22（旧 token 立即失效）、AC-23（变更审计 + 告警头）、AC-24（revoke 后拒绝）。

### P0-17 基础查询鉴权（`X-Api-Key`）

- **目标**：对设备列表、会话查询、结果查询、科研导出统一校验 `X-Api-Key`；Key 由 `.env` 注入，不落库、不进日志。
- **边界**：`/health` 与设备上报接口（走 `X-Device-Token`）不受影响；**明文 HTTP 下 Key 仍可被窃听，这是访问控制，不是传输加密**。
- **完成定义**：AC-15 通过。
- **为何在 P0**：公网 8000 暴露且无域名/网关，不加基础鉴权等于设备与结果可被任意枚举。

## 6. 开发纪律

1. 不得因为「上传要可靠」就要求设备实现 spool——那是 P1-17；
2. 不得把「设备端能算出绝对时间」当成「记录质量可升级」——派生时间只进 `quality_info.derived_time`；
3. 不得把 `X-Api-Key` 描述成传输加密；
4. 不得为了「先跑通」而给生产库执行 `alembic upgrade baseline`（存量库只能 `stamp`）；
5. 任何 P1 项**不得**写入 P0 验收。
