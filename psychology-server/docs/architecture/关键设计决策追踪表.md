## 2. v1.4 重点决策展开

### 2.1 D5（版本字段语义）

| 项 | 规则 |
| --- | --- |
| 适用范围 | **仅 `emotion_results`** |
| `emotion_results` | 无 `result_version` 列；始终单行；多批次累加后 UPDATE |
| `external_result_snapshots` | **有** `result_version`（客户端维护，B 无 `result_id`）；参与 `UNIQUE(session_id, questionnaire_code, result_version)` |
| 常见误读 | ❌「所有结果表都不能用 `result_version`」→ **不存在这条规则** |

### 2.2 D12（传输安全与加密范围）

| 项 | P0 |
| --- | --- |
| HTTPS/TLS | **不做** |
| 证书 | **不做** |
| 传输加密 | **无** |
| 加密存储 | **无** |
| 设备校时 | **不做** |
| HTTP 入口 | 保持 `:8000` |
| 日志脱敏 | **强制** |
| 查询鉴权 | **强制（P0-17）** |
| 设备身份 | **强制 P0 子集** |

> 原「安全加固专项 P1-16」（含上表对应的 P1 改造）已于 2026-11-19 由用户决定取消，不纳入后续规划。

**必须同时说明的三点**：

1. `X-Api-Key` 是**访问控制**，明文下仍可被窃听，**不等于传输加密**；
2. `subject_ref = HMAC(...)` 是**不可逆脱敏标识**，**不是加密**；
3. P0 不得在任何材料中表述为「已满足生产安全要求」。

### 2.3 时间质量（D1 的 v1.4 补充）

| 概念 | 是否落库 | 是否改变 `quality` |
| --- | --- | --- |
| `event_timestamp`（导出派生） | 否 | **否** |
| `quality`（整体质量） | 是 | 一次性写入 |
| `quality_info.derived_time` | 是（JSON） | **否** |

**P0 同步口径**：服务器会话创建时刻 ≠ 设备 CLAIM 时刻，相差 2–5 s；只能称「同会话内一致性对齐」，任何精度表述须带 `anchor_uncertainty_ms`。

### 2.4 量表编码（D2 的 v1.4 补充）

| 项 | 事实 |
| --- | --- |
| `questionnaire_code` 来源 | **客户端 `scale_id` 文本化**（实测 `22`），B 结果体无此字段 |
| 稳定性 | **待 B 确认**（X-6，P0 集成前置） |
| 未确认前 | 按现状使用；**不得**称为「永久稳定编码」 |
| `result_id` | B **没有** |
| `result_version` | **客户端维护** |
