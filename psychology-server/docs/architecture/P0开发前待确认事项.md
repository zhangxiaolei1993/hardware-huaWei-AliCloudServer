## 1. P0 阻塞事项（当前 3 项）

### B1　生产数据库迁移基线不可见

| 项 | 内容 |
| --- | --- |
| **问题** | 本次为只读审计，未连接生产服务器，无法确认生产 `psychology.db` 的真实表结构、数据量、是否存在历史 `sessions` 行、SQLite 版本与文件大小。阶段 1（Alembic 框架）与阶段 2（`sessions` 加列）需要以真实库为基线。 |
| **为什么阻塞** | 若生产库已被手工补丁（`scripts/ensure_index.py`）改过，Alembic 首次 `stamp` 的基线版本可能不一致；直接 `upgrade` 有失败风险。 |
| **需要谁确认** | 运维 / 项目负责人（提供只读基线信息，或授权执行备份与 `alembic stamp`） |
| **默认处置（未确认前）** | 只在本地副本上开发与演练；迁移脚本写成幂等、可重入；上线前完成「备份 → 副本演练 → 校验 → 执行」四步。 |
| **影响阶段** | 阶段 1、阶段 2 |

### B4　P0 是否只覆盖 PHQ-9

| 项 | 内容 |
| --- | --- |
| **问题** | `radar_norm` 归一化依赖「每个维度的满分」。目前只有 PHQ-9 有真实样本与满分依据（题库 `scores="0|1|2|3"`，满分 3）；其他量表的维度定义、满分与图表语义均未确认。 |
| **为什么阻塞** | 若 P0 要求支持其他量表，阶段 8 的归一化规则无法定稿、验收标准无法写死；若 P0 仅 PHQ-9，则可明确按 `chart2` 归一化、`chart3` 标 `unit_max_unknown` 验收。 |
| **需要谁确认** | 产品 / 服务器 B 负责人 |
| **默认处置（未确认前）** | 按「P0 仅 PHQ-9 使用完整归一化；其他量表只存原始值并标 `unit_max_unknown`，不推广 PHQ-9 规则」执行。 |
| **影响阶段** | 阶段 8、阶段 10（AC-29/AC-30） |

### B6　服务器 B 的量表稳定编码与结果唯一标识

| 项 | 内容 |
| --- | --- |
| **问题** | 结果幂等键使用 `questionnaire_code`（真实样本为 `22`），但该值来自客户端/URL 上下文，B 是否在所有响应中稳定提供「量表编码」尚未确认；样本也未提供 `result_id` 或签名。 |
| **为什么阻塞** | 若 B 无稳定量表编码，同一会话的不同量表结果可能落入同一幂等键作用域，导致误判重复（`IDEMPOTENCY_CONFLICT`），影响 A↔B 关联验收。 |
| **需要谁确认** | 服务器 B 负责人 / Flutter 端 |
| **默认处置（未确认前）** | Flutter 侧显式传 `questionnaire_code`（整数，来自 B 响应或题库元数据）；服务端做整数规范化与长度校验；无法取得时返回 422，**不猜默认值**。 |
| **影响阶段** | 阶段 8、阶段 10（AC-30/AC-31/AC-34） |

## 4. 已取消的安全加固事项（不再是 P0 阻塞项，也不进入后续规划）

| 原编号 | 事项 | 处置 |
| --- | --- | --- |
| B2 | 域名、备案、SSL 证书、443 端口 | P0 保持现有 `http://8.140.240.43:8000`，不申请域名、不部署证书、不配 Nginx HTTPS、不做 301；后续不单列计划 |
| B3 | 设备时钟未对时与 TLS 证书有效期校验 | P0 不要求 NTP/可信时间源、不要求 TLS 校验、不实现证书有效期检查与 TLS 失败处理；设备 `time.time() - t0` 保持现状 |
| B5 | 旧设备升级与 HTTP 过渡期限 | 不实施 HTTPS，**不启动 90 天倒计时** |

> **决策（2026-11-19，用户）**：原安全加固专项整体取消，不纳入后续规划。S1（全链路明文）与 S2（token 明文传输）风险仍客观存在，P0 不得对外宣称已满足生产安全要求。
> **P0 仍然强制执行**：日志脱敏（AC-27）、查询接口 `X-Api-Key`、设备身份保护 P0 子集、A 服务非 root。
