# 数据库结构说明（psychology-server）

本文按**真实 schema** 说明各表用途、关键字段与关联路径，供科研分析与二次开发使用。

- 数据库：SQLite（`DATABASE_URL`，默认 `sqlite:///./psychology.db`）
- 迁移 head：`0011_p1d_emotion_result_versions`
- 本文依据实际库副本（`alembic upgrade head` 后）的 `PRAGMA table_info / foreign_key_list / index_list` 整理
- 时间字段：库内统一为 **naive UTC**；接口/导出层再转 ISO8601

---

## 1. 表一览

| 表 | 分组 | 用途 |
| --- | --- | --- |
| `devices` | 身份 | 设备注册、token 与身份保护状态 |
| `sessions` | 主索引 | 一次测评/采集会话（**关联主键 S1**） |
| `session_devices` | 关系 | 会话与设备的绑定关系（主/辅设备） |
| `timeline_events` | 原始 | 量表/流程事件级时间轴（逐条保留） |
| `emotion_records` | 原始 | 表情识别逐帧/逐条记录 |
| `emotion_results` | 派生 | 每会话当前表情统计结果（单行当前值） |
| `emotion_result_versions` | 派生 | 结果版本历史（只追加，P1-D） |
| `external_result_snapshots` | 派生 | 外部量表结果快照（带版本链） |
| `upload_batches` | 运维 | 上传批次与幂等/完整性校验 |
| `device_connections` | 运维 | 设备连接会话 |
| `device_emotion_status` | 实时 | 设备实时表情状态（每设备一行） |
| `device_audit_events` | 审计 | 设备身份与认证审计事件 |
| `alembic_version` | 运维 | 迁移版本号 |

## 2. 核心关系

```text
devices (device_id) 1 ──── N sessions (device_id)
                            │
                            ├─ 1 ──── N session_devices (session_id, device_id)
                            ├─ 1 ──── N timeline_events (session_id)
                            ├─ 1 ──── N emotion_records (session_id)
                            ├─ 1 ──── 1 emotion_results (session_id UNIQUE)
                            │              └─ 1 ──── N emotion_result_versions (result_id)
                            ├─ 1 ──── N external_result_snapshots (session_id)
                            │              └─ supersedes_snapshot_id ──> 自身
                            └─ 1 ──── N upload_batches (session_id)

devices 1 ──── 1 device_emotion_status (device_id UNIQUE)
devices 1 ──── N device_connections (device_id)
device_audit_events.device_id 逻辑关联 devices（无 DB 外键，保留审计独立性）
```

### 2.1 S1 与 N1

- **S1 = `sessions.session_id`**：服务器生成的会话号（uuid4 hex），是表情、事件、结果、
  快照、上传批次的统一关联键，也是科研导出中的 `session_id`。
- **N1 = `sessions.external_session_id`**：外部系统（如心探探 App/小程序）的会话号，
  原样保存、可空、**不建唯一约束**；用于跨系统对账，不参与库内 join。
- 同一来源的创建幂等键：`sessions.source_system + client_request_id`
  （唯一约束 `uq_sessions_source_request`）。

## 3. 表结构要点

### 3.1 `devices`（设备）

| 关键字段 | 说明 |
| --- | --- |
| `device_id` | 业务设备 ID，唯一 |
| `device_token` | 设备认证 token（唯一索引） |
| `device_type` / `manufacturer` / `model` / `firmware_version` | 设备属性 |
| `status` / `last_seen` | 在线状态与最近心跳 |
| `capabilities` | JSON 能力声明（如 `["emotion"]`） |
| `identity_changed_at` / `token_rotated_at` / `token_revoked_at` | 身份变更/轮换/吊销时间 |

### 3.2 `sessions`（会话，主索引）

| 关键字段 | 说明 |
| --- | --- |
| `session_id` | 会话号 S1，唯一 |
| `device_id` | 主设备（FK `devices.device_id`） |
| `session_type` | 业务类型：`emotion` / 未来 `physiological` 等 |
| `source_system` | 来源：`standalone` / `xin_tan_tan` / `custom` |
| `external_session_id` | 外部系统会话号 N1 |
| `client_request_id` | 创建幂等键 |
| `status` | `created` / `running` / `completed` / `interrupted` / `aborted` |
| `started_at` / `ended_at` | 会话起止（UTC） |
| `anchor_utc_at` / `anchor_monotonic_ms` / `anchor_source` / `anchor_uncertainty_ms` | 时间锚点：相对秒 ↔ UTC 的唯一换算基准 |
| `late_upload_deadline` | 补传截止时间 |
| `ended_reason` | 结束原因 |
| `subject_ref` | 受试者脱敏标识（HMAC 截断），科研关联用 |
| `external_user_id` | 外部用户 ID（敏感，默认不导出） |
| `deprecated_identity_used` | 是否因缺少 `external_user_id` 回退旧身份计算 |

索引：`session_id`（唯一）、`device_id`、`external_session_id`、
`subject_ref`、`(subject_ref, created_at)`、`(status, ended_at)`、
`(device_id, status)`、`client_request_id`。

### 3.3 `session_devices`（会话—设备绑定）

| 关键字段 | 说明 |
| --- | --- |
| `session_id` / `device_id` | 联合关联（FK） |
| `role` | `primary` / `auxiliary` |
| `status` | `bound` / `unbound` |
| `bound_at` / `unbound_at` | 绑定/解绑时间 |

用于一场会话接入多设备（未来心率、ECG 等）：同一会话可按 `role` 找到各模态的采集设备。
当前 schema 未对 `(session_id, device_id)` 建唯一约束，写入时需按业务保证不重复。

### 3.4 `timeline_events`（事件级原始时间轴）

| 关键字段 | 说明 |
| --- | --- |
| `event_id` | 客户端事件 ID，全局唯一 |
| `session_id` | 归属会话 S1 |
| `device_id` | 设备事件必填；纯量表事件为空 |
| `stream_id` | 数据流标识（如 `app_timeline`、设备流） |
| `event_type` / `source` | 事件类型（13 类白名单）/ 来源 `device/app/server` |
| `occurred_at` / `relative_seconds` | 事件发生时间与相对锚点秒数（可为负） |
| `server_received_at` | 服务端接收时间 |
| `task_id` / `questionnaire_id` / `questionnaire_version` / `question_id` / `question_index` | 量表上下文 |
| `payload` | JSON 白名单载荷（**不含答案原文/转写**） |
| `schema_version` / `protocol_version` | 协议版本 |
| `quality` / `quality_info` | 服务端判定的质量等级与标记 |
| `client_request_id` | 上报幂等键 |

唯一约束：`(session_id, source, event_id)`；时间轴索引见 schema。

### 3.5 `emotion_records`（表情原始记录）

| 关键字段 | 说明 |
| --- | --- |
| `session_id` | 归属会话 S1 |
| `relative_seconds` | 相对锚点秒数 |
| `expression` / `confidence` | 表情与置信度（服务器最终统计以本表重算） |
| `device_timestamp` / `monotonic_ms` / `clock_offset_ms` / `frame_index` | 设备时间证据（可为空） |
| `quality` / `quality_info` | `device` / `estimated` / `missing` / `legacy` |
| `protocol_version` | 上传协议版本 |
| `device_id` / `stream_id` | 采集设备与数据流 |

索引：`(session_id, stream_id, relative_seconds)`、`(session_id, quality)`、
`session_id`、`expression`。

### 3.6 `emotion_results`（当前结果，单行）

| 关键字段 | 说明 |
| --- | --- |
| `session_id` | 唯一（`UNIQUE`），每会话仅一行当前值 |
| `client_request_id` | 结果计算批次幂等键 |
| `valid_expression_seconds` / `dominant_expression` / `average_confidence` / `face_coverage_percent` | 统计结果 |
| `result_json` | 完整结果（`expressions`、`quality`、`session_start/end`） |
| `created_at` / `updated_at` | 首次生成/最近重算时间 |

注意：重算会**覆盖**本行，历史值在 `emotion_result_versions` 中。

### 3.7 `emotion_result_versions`（结果版本，只追加，P1-D）

| 关键字段 | 说明 |
| --- | --- |
| `session_id` / `result_id` | 关联会话与当前结果行 |
| `version` | 会话内版本号，从 1 单调递增；`UNIQUE(session_id, version)` |
| `algorithm_version` | 算法口径标识（当前 `emo_v1`） |
| `status` | `generated`（当前）/ `superseded`（已被取代） |
| `trigger_source` | `first_import` / `recompute` / `manual_recompute` / `backfill` |
| `source_record_count` / `source_sha256` | 生成时参与重算的源记录数与摘要，可回溯原始数据 |
| `result_json` | 该版本完整结果快照 |
| `generated_at` / `created_at` | 生成/入库时间 |

索引：`(session_id, source_sha256)`、`session_id`。旧版本内容不依赖当前
`emotion_results`，可直接查询。

### 3.8 `external_result_snapshots`（外部量表结果快照）

| 关键字段 | 说明 |
| --- | --- |
| `snapshot_id` | 快照 ID（主键） |
| `session_id` | 归属会话 S1 |
| `source_system` / `source_result_id` | 外部来源与原始结果 ID |
| `questionnaire_code` / `questionnaire_version` / `scale_algorithm_version` | 量表与算法版本 |
| `result_version` | 同一量表结果版本号（唯一约束含此列） |
| `supersedes_snapshot_id` | 指向被取代的上一快照（自关联） |
| `status` / `trust_level` | 状态与可信度 |
| `total_score` / `scoring_mode` / `dimensions` / `radar_norm` / `risk_level` | 量表结果 |
| `source_payload_sha256` / `signature` / `signature_algorithm` | 原始载荷摘要与签名 |
| `idempotency_key` | 幂等键 |
| `received_at` / `created_at` | 接收/入库时间 |

唯一约束：`(session_id, questionnaire_code, result_version)`。

### 3.9 `upload_batches`（上传批次）

| 关键字段 | 说明 |
| --- | --- |
| `upload_id` | 批次 ID（主键） |
| `session_id` / `device_id` / `app_client_id` | 归属会话、设备、App 实例 |
| `client_request_id` | 批次幂等键 |
| `batch_type` | `event` / `emotion` / `raw` / `result` |
| `status` | `open` / `received` / `verified` / `failed` |
| `item_count` / `total_bytes` / `sha256` | 条目数、字节数、批次摘要 |
| `error_code` / `received_at` | 错误码与接收时间 |

### 3.10 设备运维表

- `device_connections`：`connection_id`（唯一）、`device_id`、`app_client_id`、
  `user_id`、`status`、`connected_at` / `disconnected_at`。
- `device_emotion_status`：每个设备一行实时状态（`device_id` 唯一），
  `face_detected` / `expression_detected` / `current_expression` / `confidence`。
- `device_audit_events`：`device_id`、`event_type`、`severity`、`source_ip`、`detail`，
  用于身份变更、token 轮换/吊销、认证失败等审计；`device_id` 为逻辑关联，无 DB 外键。

## 4. 科研分析：按会话串联多模态数据

### 4.1 串联顺序

1. **会话主表**：`sessions` 取 S1、`subject_ref`、`session_type`、时间锚点；
2. **设备**：`session_devices` + `devices` 确认采集设备与 `role`；
3. **原始数据**：
   - 量表/流程：`timeline_events`（事件级，含 `payload` 白名单字段）；
   - 表情：`emotion_records`（逐条相对时间）；
4. **派生结果**：`emotion_results`（当前）+ `emotion_result_versions`（历史版本）；
5. **外部量表**：`external_result_snapshots`（按 `result_version` 取最新/指定版本）；
6. **数据完整性**：`upload_batches` 核对批次、条数与 sha256。

### 4.2 统一时间轴

所有事件/表情的 `relative_seconds` 共用同一原点：

```text
event_timestamp ≈ sessions.anchor_utc_at + relative_seconds
```

锚点不确定度见 `anchor_uncertainty_ms`；该换算在导出/接口层动态计算，
不落库、不改 `quality`。没有可靠时间证据时，`quality` 为 `estimated` 或 `legacy`。

### 4.3 参考 SQL（单会话串联）

```sql
-- 1) 会话与设备
SELECT s.session_id, s.subject_ref, s.session_type, s.status,
       s.anchor_utc_at, s.anchor_uncertainty_ms,
       sd.device_id, sd.role
FROM sessions s
LEFT JOIN session_devices sd ON sd.session_id = s.session_id
WHERE s.session_id = :sid;

-- 2) 事件时间轴（只取白名单字段）
SELECT event_id, event_type, source, relative_seconds,
       occurred_at, quality, payload
FROM timeline_events
WHERE session_id = :sid
ORDER BY relative_seconds, id;

-- 3) 表情原始记录
SELECT relative_seconds, expression, confidence, quality,
       device_timestamp, monotonic_ms, frame_index
FROM emotion_records
WHERE session_id = :sid
ORDER BY relative_seconds, id;

-- 4) 当前结果与全部版本
SELECT * FROM emotion_results WHERE session_id = :sid;
SELECT version, status, algorithm_version, trigger_source,
       source_record_count, source_sha256, result_json
FROM emotion_result_versions
WHERE session_id = :sid
ORDER BY version;

-- 5) 外部量表快照（每个量表取最新版本）
SELECT *
FROM external_result_snapshots e
WHERE e.session_id = :sid
  AND e.result_version = (
      SELECT MAX(x.result_version)
      FROM external_result_snapshots x
      WHERE x.session_id = e.session_id
        AND x.questionnaire_code = e.questionnaire_code
  );
```

### 4.4 多模态扩展方式

- 新模态（心率、ECG、血液检测）继续复用 `sessions` 作为主索引，
  用 `session_type` 区分业务，用 `session_devices.role` 关联采集设备；
- 行级数据建议沿用 `session_id + relative_seconds + stream_id + quality`
  的原始记录模式；大数据/波形以“元数据表 + 分段/文件”扩展，不塞进现有表；
- 分析结果继续采用“当前值 + 只追加版本表”的模式，保证可追溯。
