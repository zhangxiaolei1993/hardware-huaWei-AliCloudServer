# P0 验收标准清单（v1.4 对齐版）

| 项目 | 内容 |
| --- | --- |
| 依据文档 | 《AI 心探探多模态数据采集平台总体架构设计说明书 **v1.4**》§21.3 / §21.4 / §19.2 |
| 制定日期 | 2026-11-17 |
| 适用范围 | P0 业务功能开发与端到端联调阶段的验收 |
| P0 验收范围 | **AC-01…AC-24、AC-27、AC-29…AC-36**（共 33 条；其中 AC-05 以 AC-05a 计入） |
| 不在 P0 范围 | AC-05b（P1-17）、AC-25 / AC-26 / AC-28（P1-16 安全专项） |
| 本轮性质 | 只出清单，不执行任何测试、不连生产 |

> **前置声明**：P0 使用明文 HTTP。本清单**没有任何一条**用于证明「传输安全」或「生产安全达标」；安全验收属 P1-16 专项。

## 1. 功能验收用例（P0 必过）

| # | 场景 | 预期结果 | 关联任务 |
| --- | --- | --- | --- |
| AC-01 | 老客户端（不传 `source_system` / `external_session_id`）建会话 | 201；`source_system='standalone'` | P0-1 |
| AC-02 | 同 `(source_system, client_request_id)` 建两次 | 第二次 200 `{created:false}`，`session_id` 相同 | P0-1 |
| AC-03 | 同一设备已有 running 会话，再建不同外部 ID | 409 `SESSION_ALREADY_ACTIVE` + `active_session_id` | P0-1 |
| AC-04 | 同一批次 `client_request_id` 重复上传 | 第二次 `duplicate:true`；`emotion_records` 行数不变 | P0-5 |
| **AC-05a** | **正常网络下**上传失败重试 / 服务重启后重试 | 不产生重复入库；同会话重复提交命中幂等；**只验服务端，设备端零改动** | P0-4、P0-5 |
| AC-06 | 上传含 `answer_value` 的事件 | 400，整批拒绝，不部分入库 | P0-3 |
| AC-07 | 同一 `idempotency_key` 同步结果两次 | 第二次 `duplicate:true`，快照不重复 | P0-4 |
| AC-08 | 结果同步时 A 不可用，恢复后重试 | 最终成功；`trust_level='client_relayed'` | P0-4、P0-12 |
| AC-09 | `relative_seconds = -3` | 200；`quality_info.flags` 含 `pre_anchor` | P0-8 |
| AC-10 | `relative_seconds` 超会话时长很多 | 200 + `out_of_range` 标记（不整批 422） | P0-8 |
| AC-11 | 会话 `completed` 后首次补充上传 | 在 `late_upload_deadline` 内 200 | P0-1、P0-5 |
| AC-12 | 会话 `aborted` 后上传 | 409 `SESSION_ABORTED` | P0-1 |
| AC-13 | 一会话绑 2 台设备，各上传 | 均入库，按 `device_id` 可区分 | P0-6 |
| AC-14 | `session_type` 传 `emotion` / `multimodal` | 均 201 | P0-2 |
| **AC-15** | 未带 / 带错 `X-Api-Key` 访问 `GET /devices`、`GET /sessions`、`GET .../result` | 401 `UNAUTHORIZED`；带正确 Key → 200；设备上报（`X-Device-Token`）与 `/health` **不受影响** | **P0-17** |
| AC-16 | 旧固件原始请求（仅三字段 + `session_meta` + `client_request_id`） | 200；`quality=legacy`；`stream_id=facial_expression`；flags 含 `batch_upload`/`stream_defaulted`/`clock_unverified` | P0-7、P0-14 |
| AC-17 | v2 请求带 `stream_id` 但缺 `device_timestamp` | 200；`quality=missing`（**P0 不产出 `estimated`**）；绝不为 `device` | P0-7 |
| AC-18 | 任意请求缺 `device_timestamp` | `server_received_at` 只写接收列，**不参与**质量判定、不回填为设备时间 | P0-7 |
| AC-19 | 任意上传响应 | 含 `X-Protocol-Accepted: 1.0,2.0`；`stream_id` 被默认时含 `X-Compat-Warning` | P0-14 |
| AC-20 | 用 v1 URL + 原三字段连续上传（多次会话） | 永不 404 / 422；v1 路径保持可用 | P0-14 |
| AC-21 | 客户端在 body 伪造 `quality="device"` | 服务器忽略，按真实字段推导 | P0-7、P0-14 |
| AC-22 | 管理员 `rotate-token` 后旧 token 再请求 | 旧 token 立即 401；新 token 正常；审计有 `token_rotated` | P0-15 |
| AC-23 | 同一 `device_id` 用不同 `model`/`manufacturer` 重新注册 | 注册仍成功（幂等）；`device_audit_events` 有 HIGH 记录；响应头 `X-Identity-Warning: changed` | P0-15 |
| AC-24 | `revoke` 后再注册 / 再上传 | 注册 403 `DEVICE_REVOKED`；上传 401；`reinstate` 后新 token 可用 | P0-15 |
| AC-27 | 检查 A 应用日志 | **不含** `Authorization` / `X-Device-Token` / `X-App-Key` / 答案 / 转写原文（**日志脱敏属 P0 强制项**；Nginx access log 待 P1-16） | 阶段 9 |
| AC-29 | 同步请求携带 `score_list` 或 `radar_charts.chart1_phq9_items` | 422 `FORBIDDEN_FIELD`；**不得因缺 `chart1` 报错** | P0-4 |
| AC-30 | 用真实样本（`session_id=1742`，仅 `chart2`+`chart3`）构造请求 | 201；`dimensions` 恰 7 项；`series[chart2].norm=0.2233/0.6667/0.3333` 且 `unit_max_source=bank_scores`；`series[chart3].norm_status=unit_max_unknown` 且 `norm` 全 `null`；`scoring_mode=option`、`state_update_status=scheduled` 入库 | P0-4 |
| AC-31 | 同一样本重放；同 key 改 `total_score` 重发 | 前者 200 `duplicate:true`；后者 409 `IDEMPOTENCY_CONFLICT`（不改写原行） | P0-4 |
| AC-32 | 同一 N1、换新 `client_request_id` 再建 | 两次均 201，生成两个不同 S1；`external_session_id` 原样为 N1；**不判重、不覆盖** | P0-1 |
| AC-33 | `source_system` 传 `legacy_app` / `custom` / 任意串 | `legacy_app` 与任意值 → 422 `INVALID_SOURCE_SYSTEM`；`custom` → 403 `SOURCE_SYSTEM_NOT_ALLOWED` | P0-1 |
| AC-34 | 同一 N1 的两个 S1 分别同步结果 | 各自独立入库（键 `res:{session_id}:...`），互不覆盖、不串号 | P0-1、P0-4 |
| **AC-35** | 对 `quality=missing`/`legacy` 旧数据执行导出 | 导出物含派生 `event_timestamp` 且 `manifest` 标 `estimated`；`quality_info.derived_time` 含 `source`/`method`/`anchor_uncertainty_ms`；**库内 `quality` 与 `flags` 未被修改** | P0-7、导出器 |
| **AC-36** | `questionnaire_code` 传 `"022"` / `"22.0"` / `"PHQ-9"` | 422 `IDEMPOTENCY_KEY_MALFORMED`；且验收材料**不得**声称该编码永久稳定（待 X-6） | P0-4 |

## 2. 明确不在本清单的验收项

| 编号 | 内容 | 归属 | 原因 |
| --- | --- | --- | --- |
| AC-05b | 断网 1 小时 / 采集中进程重启后补传，数据完整无重复 | **P1**（P1-17） | 设备当前无持久化队列（AD-8） |
| AC-25 | 公网 HTTPS、443、证书链、HTTP→HTTPS 301 | **P1**（P1-16 / SS-08） | P0 不实施 TLS |
| AC-26 | 旧固件 HTTP 过渡期可用 + `X-Protocol-Required` | **P1**（P1-16 / SS-15） | 过渡入口随安全专项上线 |
| AC-28 | 证书过期/握手失败不降级 | **P1**（P1-16 / SS-11） | 无 TLS 则无此场景 |

> **纪律**：上述 4 条**不得**以「先做一版」的名义塞回 P0；AC-05b 尤其不能通过「留底 JSON 人工重发」充当证据（留底文件不自动重扫，见 §15.7）。

## 3. 数据质量指标（P0 基线）

| 指标 | 目标 | 说明 |
| --- | --- | --- |
| 质量标签覆盖率 | 100% 记录有 `quality` | 旧数据回填 `legacy` |
| 误标率 | 0（`server_received_at` 不得被当作采集时间） | AC-18 把关 |
| `estimated` 误用 | 0（P0 不产出 `estimated`） | 设备无 `monotonic_ms`/锚点 |
| 批次幂等 | 重复上传 0 重复行 | AC-04 / AC-05a |
| 派生时间标注率 | 派生 `event_timestamp` **100%** 带 `anchor_uncertainty_ms` | AC-35；默认 5000 |
| 质量不提升 | 派生后 `quality` 变更次数 = 0 | AC-35 |

## 5. 验收结论口径（禁止夸大）

1. **可以说**：P0 业务链路可跑通、数据可关联、上传幂等、质量可标注、设备身份可审计、查询需鉴权。
2. **不可以说**：传输安全、生产安全达标、跨模态精确同步、量表编码永久稳定、断网补传已实现。
3. 任何精度/安全表述必须同时给出限定：`anchor_uncertainty_ms`（同步）、「明文 HTTP 阶段性安排」（安全）、「待 B 确认」（编码）。
