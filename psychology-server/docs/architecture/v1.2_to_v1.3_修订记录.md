# v1.2 → v1.3 修订记录

> 对应文档：《AI 心探探多模态数据采集平台总体架构设计说明书》
> 修订版本：v1.2（架构修订版） → **v1.3（阶段调整版）**
> 修订日期：2026-11-17
> 修订性质：**实施阶段调整**。P0 暂不实施 HTTPS/TLS、证书部署、设备校时及相关加密改造，先完成业务功能开发与端到端联调；安全加固转为后续独立专项。
> 本次是否修改代码 / 数据库 / 服务器配置：**没有**。仅编辑/新增 Markdown 文档。

---

## 0. 修订背景

项目负责人调整实施顺序：

1. 当前阶段优先打通业务链路：设备注册/心跳、会话创建与结束、表情时间线上传、上传幂等、A 存储与统计、Flutter 联调、A↔B 关联、查询与验收。
2. HTTPS/TLS、证书、Nginx、设备校时、Token 传输保护等转入**后续安全加固专项（P1-16）**。
3. **不是取消安全要求**，只是调整阶段；P0 期间明示明文风险，不得表述为已满足生产安全。

### R2　P0 移除设备校时与 TLS 证书校验

| 项 | 内容 |
| --- | --- |
| **修改章节** | §8.1/§8.2（能力分层说明保持）、§17.2、§17.5.2、§17.5.3、§19.3 P1-4、§22 D12 |
| **原有问题** | v1.2 的 P0 隐含要求设备支持 TLS 校验，而设备时钟未对时（AD-3），会出现「证书有效期校验失败导致无法上传」的硬阻塞；同时要求 NTP 会引入设备端改造。 |
| **修改内容** | ① 明确 P0 保持 `relative_seconds = time.time() - t0` 现状，不要求 NTP/可信时间源；② 不要求设备支持 TLS 证书校验、不实现证书有效期检查与 TLS 失败处理；③ 设备端改造表阶段列 P0 → P1；④ P1-4 的 NTP 归入 P1-16；⑤ 时间质量规则不受影响（仍按 §8.4 三层校验，`server_received_at` 只代表接收时间）。 |
| **修改原因** | 消除「设备时钟 → 证书校验 → 上传失败」的 P0 死锁；时间能力仍如实分层，不伪造可信 UTC。 |
| **影响数据库** | 否。 |
| **影响 API** | 否。 |
| **影响 P0 开发** | 是（设备端 P0 无时间/证书改造任务）。 |
