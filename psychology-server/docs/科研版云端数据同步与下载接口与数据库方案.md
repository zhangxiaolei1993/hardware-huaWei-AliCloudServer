## 0. 方案摘要

### 0.1 一句话方案

在现有「以会话为中心」的采集服务旁边，增加一层**科研管理域**：

```
research_projects / research_groups / research_participants
        ↓
sessions（现有，新增 participant_id / project_id / group_id / data_origin）
        ↓
research_assessments（新增，1 个会话 × 1 个量表 = 1 条测评）
        ↓
external_result_snapshots（现有，新增 assessment_id / participant_id，保留版本历史）
        ↓
research_conversations / research_conversation_messages（新增）
        ↓
emotion_results / emotion_records（现有，按 session_id 关联）
        ↓
research_export_jobs → 科研数据包（CSV / JSON）
```

## 1. 审计报告 §7 的 29 条逐条结论

### 1.1 测评记录口径（对应审计报告 §7.1）

| # | 问题 | 结论 | 理由 / 影响 |
|---:|---|---|---|
| 1 | assessment 粒度：会话还是量表提交 | **一次会话 × 一个量表 = 一个 assessment** | 一个会话可能包含多个量表；把 assessment 挂在会话上会导致多量表无法区分。同一量表在同一会话内重传/改版用 `result_version` 表达，不新增 assessment。 |
| 2 | 是否独立 assessment 表 | **是，新增 `research_assessments`** | 只有独立表才能稳定承载 `participant_id`、`questionnaire_code`、`reported_at`、`assessment_status`，并支撑「每被试每量表最新一次」查询；只在快照上加字段会导致同一会话多量表时无法编号。 |
| 3 | 同一被试同一量表重复测评 | **跨会话 = 新 assessment；同会话 = 同 assessment 的新 version** | `UNIQUE(session_id, questionnaire_code)` 保证会话内唯一；跨会话自然产生多条 assessment，历史不覆盖。 |
| 4 | 「最新一次」判定 | **`reported_at DESC, created_at DESC, assessment_id DESC`** | `reported_at` 是客户端报告的完成时间，最接近实验事实；为空时回退 `created_at`；最后用 `assessment_id` 保证确定性。不用 `result_version`，因为它只在同一会话内有意义。 |

## 2. 四个关键决策详述

### 2.1 决策一：测评记录粒度与独立 `assessment_id`

**结论：新增 `research_assessments`，粒度 = 一次会话 × 一个量表。**

关系：

```
research_participants 1 ──< sessions 1 ──< research_assessments 1 ──< external_result_snapshots
                                              │
                                              └──< research_assessment_items（可选，逐题）
```

- `research_assessments` 唯一键：`UNIQUE(session_id, questionnaire_code)`。
- 同一会话内同一量表再次提交（`result_version` 2、3…）：
  - 不新增 assessment；
  - 新快照仍写入 `external_result_snapshots`，`assessment_id` 指向同一 assessment；
  - 更新 `research_assessments.current_snapshot_id`、`result_version`、`total_score`、`assessment_status`；
  - 旧快照永久保留。
- 同一被试换一个会话再测同一量表：
  - 新增一条 assessment；
  - 「最新一次」按 `reported_at` 排序取第一条。
- 不在 `sessions` 上加 `assessment_id`：因为一个会话可以有多个量表，加在会话上是错误基数。`sessions` 只加 `participant_id/project_id/group_id`。

> **边界情况：** 如果研究设计需要「同一会话内同一量表连续施测两次」（例如前测/后测都在一个会话），当前 `UNIQUE(session_id, questionnaire_code)` 会阻止第二次建档。此时需要把唯一键改为 `(session_id, questionnaire_code, attempt_no)`，并让客户端显式传 `attempt_no`。本期默认不支持；如确有需要，请在开发前确认。

**为什么不把 `assessment_id` 只放在快照表：**

- 快照是「结果版本」，同一 assessment 会有多条；把 assessment_id 放在快照上仍需要一个主表来承载「这次测评属于谁、何时、哪个量表」。
- 独立表可以挂逐题作答、对话、下载筛选，不会被版本重传拆散。

### 2.2 决策二：权限模型（本轮不做）

**结论：本轮不建账号体系、不建成员表、不做主站 introspection。**

用户口径原话：「账号你不用管，我申请独立账号登录就行，这部分你都不用管」「不要管任何安全的问题不用改」。

落地方式：

- 所有 `/api/v1/research/*` 与现有接口一致，仅依赖 `X-Api-Key`（`require_api_key`）。
- 不创建 `research_project_members`；没有 owner/editor/viewer 概念。
- 「调用者是否有权限操作某个项目」**不校验**；在 `app/api/research.py` 的写接口处保留 `TODO(PERMISSION)`，后续接入账号体系时在此补，路径与响应结构不变。
- `research_export_jobs.requested_by` 保留字段但写 `NULL`；`requested_ip` 继续记录来源 IP。

**遗留空位（明确列出）：**

1. 任何人拿到 `X-Api-Key` 即可读写全部项目数据。
2. 下载任务无法区分「谁下载了什么」。
3. 跨项目访问不会返回 403/404，因为没有项目归属校验。

以上均属后续「账号与权限」阶段，不在本轮修复；也不在代码中臆造账号、角色或凭证校验。

### 2.3 决策三：被试字段范围

**结论：用户已拍板「全部上云」，姓名、电话同样上云。**

| 字段 | 是否上云 | 说明 |
|---|---|---|
| `participant_id` | 是 | 云端生成 |
| `participant_code` | 是 | P001 等编号，项目内唯一 |
| `name` | **是** | 用户明确要求上云 |
| `phone` | **是** | 用户明确要求上云 |
| `project_id` / `group_id` | 是 | 归属；组名为用户自定义 |
| `gender` | 是（可选） | 人口学 |
| `age` | 是（可选） | 整数；不建议存出生日期 |
| `school` | 是（可选） | 学校 |
| `grade` | 是（可选） | 年级 |
| `status` | 是 | active / archived |
| `source_local_id` | 是 | 仅用于迁移映射 |
| `notes` | 否 | 本轮不设计该字段 |

**影响：** 云端与下载包均包含姓名、电话；使用与共享需遵循知情同意与项目内数据管理要求。

### 2.4 决策四：本地历史数据迁移

**结论：显式迁移向导、只读复制、不删除本地、可回退、可核对。**

流程（设计，不实现）：

1. **止血**：先把本地 `research_results_*` 的 20 条上限取消（或提高），确保迁移前不再删旧记录。
2. **备份**：
   - 平板：复制 `research_participants.json` 与结果导出文件到独立目录；
   - 云端：迁移前做数据库文件备份；
   - 生成一份「迁移前全量导出 zip」作为第三份凭证。
3. **建项目/组**：科研管理员在云端创建科研项目与实验组。
4. **被试映射**：
   - 本地每条被试 → 调用批量同步；
   - `source_local_id = 本地 ResearchParticipant.id`；
   - 云端按 `(project_id, participant_code)` 去重；
   - 返回 `participant_id` 并写回本地。
5. **测评迁移**：
   - 本地结果若有 `s1_session_id` 且云端存在 → 直接挂接；
   - 若没有会话或云端不存在 → 创建 `data_origin='legacy_import'` 的合成会话（`status=completed`、`session_type=assessment`、`anchor_utc_at=reported_at`、`source_system=standalone`）；
   - 再创建 assessment 与结果快照。
6. **去重**：
   - 迁移幂等键：`legacy:{project_id}:{participant_id}:{questionnaire_code}:{source_payload_sha256}`；
   - 相同 → 跳过；不同 → 新建 assessment，绝不覆盖。
7. **核对**：
   - 被试数、每量表条数、总分合计、时间范围、编号列表；
   - 生成 `migration_report.json`，用户确认后才标记 `migrated_at`。
8. **保留**：本地数据永不删除；只写 `cloud_participant_id` / `migrated_at` 标记。

**已拍板：**

- 纯离线历史测评**允许**出现在云端，无 S1 时创建 `data_origin='legacy_import'` 的合成会话。
- 旧数据若没有 `source_payload_sha256`，服务端用「项目 + 被试 + 量表 + 报告时间 + 稳定化后的 payload」生成摘要作为幂等键；同一内容重复导入跳过。
- 迁移接口仅运维使用，默认 `dry_run=true`，不删除本地数据。

### 3.4 一致性规则（重要）

| 场景 | 规则 |
|---|---|
| 被试改编号 | 只改 `research_participants.participant_code`；历史 `sessions` / `assessments` 不重写，导出时按 `participant_id` join 取当前编号 |
| 被试换组 | `research_participants.group_id` 表示**当前组**；`sessions.group_id` / `assessments.group_id` 保留**施测时组别**，不随被试换组而更新 |
| 按组下载 | `scope.mode=group` 按被试**当前组**筛人；`group_ids` 或 `group_names` 均**精确匹配**。包内 `sessions.csv` / `assessments.csv` 同时给出施测时 `group_id` / `group_name` |
| 归档被试 | 默认列表不返回；按项目/组下载时默认排除 `archived`，可通过参数显式包含 |
| 结果版本 | 同一 assessment 的旧快照永久保留；`current_snapshot_id` 指向最新版本 |
| 删除 | API 不提供物理删除；归档不影响历史下载 |

> 「按当前组筛人、按施测时组别出数」是有意设计：前者符合实验管理直觉，后者保证历史数据不被后续换组污染。本轮未提供 `group_basis=session` 参数；如后续需要，再作为可选参数加入。

## 7. 接口设计

> 统一约定：
> - 新接口前缀 `/api/v1/research`，资源名避开旧接口。旧 `GET /research/sessions` 保留；新会话查询用 `experiment-sessions`。
> - 鉴权：**本轮统一 `X-Api-Key`**（与现有查询/导出接口一致）；不做 Bearer、不做 introspection、不做项目成员校验。
> - 响应时间：ISO8601 带 `+08:00`。
> - 分页：`page`（默认 1）、`page_size`（默认 50，最大 200）；返回 `{items, page, page_size, total}`。
> - 错误：沿用 FastAPI 默认 `{"detail": "<错误码: 说明>"}`；业务错误码写在 `detail` 字符串前缀中（如 `ROW_VERSION_CONFLICT: ...`）。

### 7.1 鉴权上下文（本轮不提供）

- **不实现** `GET /api/v1/research/auth/context`。
- 原因：本轮不做账号体系，没有「当前用户 / 可访问项目 / 角色」概念。
- 平板侧如需判断可用项目，直接调用 `GET /api/v1/research/projects`（仅 `X-Api-Key`），由上层业务自行选择项目。
- 后续接入账号后，再新增该接口返回 `user_id`、`projects` 与角色；路径可复用，不破坏现有接口。

```json
  "started_at": "2026-11-23T10:00:00+08:00"

```

- 响应：对话对象 + `created`（`true/false`）。

#### POST /api/v1/research/conversations/{conversation_id}/messages

- 鉴权：`X-Api-Key`
- 请求体：

```json
{
  "messages": [
    {
      "message_id": "msg_ab12...",
      "seq": 1,
      "role": "assistant",

```

- 限制：1~500 条/次；单条 `content` ≤ 64KB。
- 幂等：同 `(conversation_id, seq)` 且同 `message_id` → 跳过计数；同 `seq` 不同 `message_id` → 409 `SEQ_CONFLICT`。
- 响应：`{conversation_id, inserted, skipped, message_count, content_sha256}`。

### 7.7 下载中心

#### POST /api/v1/research/download-jobs

- 鉴权：`X-Api-Key`
- 行为：创建异步任务，立即返回 202。
- 请求体：

```json
{
  "project_id": "prj_...",
  "scope": {
    "mode": "group",
    "group_ids": ["grp_..."],
    "participant_ids": []
  },
  "assessment_scope": {
    "mode": "latest_per_scale",
    "from": "2026-09-01T00:00:00+08:00",
    "to": "2026-11-30T23:59:59+08:00",
    "questionnaire_codes": ["1", "2"],
    "session_ids": []
  },
  "data_types": [
    "participants",
    "sessions",
    "assessments",
    "expression_summary",
    "expression_timeline",
    "conversation",
    "devices"
  ],
  "format": "both"
}
```

- `scope.mode`：
  - `all`：项目全部被试；
  - `group`：按 `group_ids` 或 `group_names`（均精确匹配；组名用户自定义）；
  - `participants`：按 `participant_ids`（最多 500）。
- `assessment_scope.mode`：
  - `all`：全部历史测评；
  - `latest_per_scale`：每被试每量表最新一次；
  - `date_range`：按 `reported_at` 范围；
  - `questionnaire`：按量表；
  - `session`：按会话。
- `data_types`：`participants/sessions/assessments/assessment_items/expression_summary/expression_timeline/conversation/devices`。
- `format`：`csv/json/both`（默认 `csv`）；`both` 时同名 `.csv` 与 `.json` 并存。
- `include_archived`：是否包含已归档被试，默认 `false`。
- 响应：

```json
{
  "export_id": "rex_...",
  "project_id": "prj_...",
  "status": "queued",
  "progress_current": 0,
  "progress_total": 0,
  "counts": null,
  "filters": {"scope": {"mode": "all"}, "format": "csv"},
  "created_at": "2026-11-23T11:00:00+08:00",
  "expires_at": "2026-11-30T11:00:00+08:00"
}
```

- 返回 `202 Accepted`；任务在后台执行。

#### GET /api/v1/research/download-jobs/{export_id}

- 鉴权：`X-Api-Key`
- 响应：

```json
{
  "export_id": "rex_...",
  "status": "running",
  "progress_current": 12,
  "progress_total": 80,
  "counts": {"participants": 30, "sessions": 80, "assessments": 140},
  "file_name": null,
  "file_size": null,
  "sha256": null,
  "created_at": "...",
  "started_at": "...",
  "finished_at": null,
  "expires_at": "...",
  "error_code": null
}
```

- 状态机：`queued → running → succeeded | failed | cancelled | expired`。
- 轮询建议：启动后 1 秒，之后 2 秒；超过 10 分钟提示用户稍后回来。

#### GET /api/v1/research/download-jobs/{export_id}/download

- 鉴权：`X-Api-Key`
- 行为：`succeeded` 时返回 zip；其他状态 409 `EXPORT_NOT_READY`；过期 410 `EXPORT_EXPIRED`。

#### DELETE /api/v1/research/download-jobs/{export_id}

- 鉴权：`X-Api-Key`
- 行为：仅 `queued` 可取消；`running` 返回 409；`succeeded` 只删除产物并标记 `expired`。

#### GET /api/v1/research/download-jobs

- 鉴权：`X-Api-Key`
- 参数：`project_id?`、`status?`、`page`、`page_size`（本轮无账号，不支持 `mine` 过滤）
- 返回任务列表，用于「下载历史」。

#### 分页与异步结论

- 列表类接口（被试、会话、测评、对话）全部 `page/page_size`。
- 下载类接口全部异步任务，不做同步 zip；旧的同步导出接口保持不变。
- v1 不支持断点续传；包过大时按任务失败并提示缩小筛选范围（阈值建议：zip > 2GB 或行数 > 500 万）。

### 7.8 历史迁移专用接口

#### POST /api/v1/research/import/legacy

- 鉴权：`X-Api-Key`；**仅服务端/运维调用**，不暴露给平板。
- 用途：一次性导入本地备份数据，支持 dry-run。
- 请求体：

```json
{
  "project_id": "prj_...",
  "dry_run": true,
  "participants": [
    {
      "source_local_id": "local_9f2c",
      "participant_code": "P001",
      "name": "张三",
      "phone": "13800000000",
      "group_id": "grp_...",
      "group_name": "实验组 A",
      "gender": "female",
      "age": 15,
      "school": "某某中学",
      "grade": "初二"
    }
  ],
  "assessments": [
    {
      "source_local_id": "local_9f2c",
      "questionnaire_code": "1",
      "reported_at": "2026-09-01T10:00:00+08:00",
      "s1_session_id": null,
      "total_score": 12,
      "result_payload": {}
    }
  ]
}
```

- 行为：
  - `dry_run=true`：用未落库的临时对象预测将创建/复用的条数，最后 `rollback()`，不留下任何数据；
  - `dry_run=false`：创建被试、合成会话（无 S1 时，`data_origin='legacy_import'`，`device_id='legacy_import'`）、assessment、快照；
  - 组名不存在时自动建组；
  - 幂等：`legacy:` + sha256(project_id|participant_id|questionnaire_code|reported_at|payload_sha)；
  - 永不删除本地数据。
- 响应（`migration_report`）：

```json
{
  "dry_run": true,
  "participants_created": 1,
  "participants_reused": 0,
  "sessions_created": 1,
  "assessments_created": 1,
  "assessments_skipped": 0,
  "errors": []
}
```

## 8. 统一鉴权与权限矩阵

### 8.1 凭证类型（第三阶段实际）

| 凭证 | 使用方 | 适用接口 | 现状 |
|---|---|---|---|
| `X-Api-Key` | 科研版平板 / 运维 / 旧 APK | **全部** `/api/v1/research/*` 及现有查询、旧导出 | 已使用；默认值风险见 §10.1，本轮按用户要求不动 |
| `X-Device-Id` + `X-Device-Token` | Atlas 设备 | 心跳、表情上传、设备状态 | 已有，不受影响 |
| `connection_id` | 手机端 | 创建会话、断开连接 | 已有，不受影响 |

> 主站 `voucher` / Bearer / introspection：**本轮不实现**。

### 8.2 权限矩阵（第三阶段实际）

| 能力 | `X-Api-Key` | 设备 token |
|---|---|---|
| 查看/新建/编辑/归档 项目、组、被试 | ✓ | ✗ |
| 查看会话、测评、逐题作答 | ✓ | ✗（沿用现有设备归属校验） |
| 绑定会话到被试 | ✓ | ✗ |
| 上传对话正文 / 读取正文 | ✓ | ✗ |
| 创建下载任务 / 下载 | ✓ | ✗ |
| 迁移导入 | ✓ | ✗ |
| 旧科研导出 | ✓ | ✗ |

> 本轮没有 viewer/editor/owner，也没有「项目成员」概念，因此不存在按角色的权限差异。

### 8.3 校验点（第三阶段实际）

1. **认证**：`Depends(require_api_key)` 校验 `X-Api-Key`；失败 401。
2. **项目级授权**：**未实现**。写接口处保留 `TODO(PERMISSION)`；任何持钥调用者可操作任意项目。
3. **资源归属**：服务层按 `project_id` / `participant_id` / `session_id` 查询，但**不做调用者归属校验**；查询不到返回 404。
4. **会话归属**：`assign_participant` 校验 participant 存在；`session.participant_id` 已有其他值时返回 409。
5. **下载审计**：任务创建时写 `requested_ip/filters_json`；`requested_by` 写 `NULL`；下载时只校验任务状态与是否存在，不校验归属。

**遗留空位（后续账号权限阶段处理）：** 项目级 403、角色校验、下载任务归属校验、`requested_by` 填充。

## 10. 风险与修复方案

### 10.1 P0：生产默认 `X-Api-Key` 可读全量科研数据（本轮不动）

> **用户已明确：「不要管任何安全的问题不用改」**。本节仅保留方案记录，本轮**不换密钥、不改鉴权、不做证书/审计/加固、不改生产配置**。

**现状证据：** 审计报告 §0、§8.3；生产 `GET /api/v1/devices`、`GET /api/v1/research/sessions` 带 `change-me-query-key` 返回 200。

**目标：**

1. 生产不再接受默认密钥；
2. 科研版 APK 不再内置长期共享密钥；
3. 旧手机版功能不被误伤。

**分阶段方案（推荐）：**

| 阶段 | 动作 | 影响面 |
|---|---|---|
| 1. 双密钥支持（代码改动） | `security.py` 增加 `QUERY_API_KEY_PREVIOUS`，同时接受新旧两把；新密钥放 `.env`，旧密钥进 previous | 所有旧客户端继续可用；新增配置项 |
| 2. 部署并轮换 | 生成 32 字节随机密钥；更新 `.env`；重启；验证旧密钥仍可用、新密钥可用 | 无中断 |
| 3. 发布新 APK | 科研版通过 `--dart-define` 注入新密钥；同时移除 `emotion_dio.dart` 的默认值，缺失时构建失败 | 旧 APK 仍靠 previous 可用 |
| 4. 观察与收敛 | 观察 14 天 401 日志；确认无旧客户端后移除 `QUERY_API_KEY_PREVIOUS` | 旧 APK 失效，必须升级 |
| 5. 中长期 | 科研查询改用 Bearer；`X-Api-Key` 仅服务端/运维；APK 不内置 | 需要 Flutter 改造与主站 introspection |

**最小改动替代方案（不推荐）：** 直接换密钥并强制升级 APK。改动最小，但会造成旧 APK 立即 401，实验现场可能中断；仅在能确保所有平板当天升级时使用。

**其他注意：**

- 不要轮换 `RESEARCH_SALT`：它影响 `subject_ref` 的连续性；如需轮换，必须保留旧 salt 验算或接受历史 `subject_ref` 不可比。
- 密钥只放服务端 `.env`，不写入代码、不写入文档、不进 git。
- 建议同时加访问日志与 401 告警；可选加 IP 白名单（会限制移动网络，慎用）。

### 10.2 P1：Flutter `status: 'interrupted'`（已实施服务端兼容）

**现状证据：** 审计报告 §3.3；服务端 `SessionStatusUpdateRequest` 原来只接受 `running/completed/aborted`，Flutter 发送 `interrupted` 且 `catchError` 静默吞掉。

**已实施（方案 A）：**

- `SessionStatusUpdateRequest.status` 扩展为 `running/completed/aborted/interrupted`；
- `interrupted` 仅作为**输入别名**，落库统一为 `aborted`，并写 `ended_reason='client_interrupted'`；
- 响应仍返回 `status='aborted'`，旧客户端无感知；
- 不改数据库枚举，不改现有状态值；
- 已由测试覆盖。

**方案 B（客户端修正）：**

- Flutter 改为发送 `aborted`，并新增 `ended_reason='client_interrupted'`；
- 去掉 `catchError((_) {})`，至少记录日志并在下次启动重试；
- 需要发布新 APK；旧 APK 仍会 422。
- 影响：客户端改动明确，但无法修复已发布的旧版本。

**推荐组合：A + B。** 先上 A 保证旧 APK 也能落状态；再在科研版 APK 中用 B 规范语义。

**附带安全修复（建议同批）：**

- 当前 `POST /sessions/{sid}/status` 免认证；建议后续要求 `connection_id` 或设备 token，并校验会话归属。
- 为兼容旧 APK，可分两步：先接受可选 `connection_id` 并校验（不强制），发布新 APK 后再强制。
- 在强制之前，至少对 `status` 接口加限流与审计日志。
