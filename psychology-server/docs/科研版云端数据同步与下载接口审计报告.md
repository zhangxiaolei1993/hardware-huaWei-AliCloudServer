## 2. 九项核实结论

### 2.1 登录认证与当前用户体系

**结论：psychology-server 没有登录、没有用户表、没有课题组/项目级权限。**

1. **Token 形式**
   - 查询/管理/导出：唯一共享密钥，请求头 `X-Api-Key`。校验逻辑见 [security.py](file:///f:/software_self/华为开发/hardware-aiLiYun/psychology-server/app/core/security.py#L30-L95)：`_api_key_matches()` 用 `hmac.compare_digest` 与 `settings.query_api_key` 比较。
   - `require_api_key`、`require_research_api_key`、`require_app_key` 三个依赖最终都校验同一个 `X-Api-Key`；其中 `require_app_key` 是旧名，旧头 `X-App-Key` 已不再接受。
   - 设备侧：`X-Device-Id` + `X-Device-Token`，64 位十六进制，注册时下发，见 [security.py](file:///f:/software_self/华为开发/hardware-aiLiYun/psychology-server/app/core/security.py#L122-L173) 与 `generate_device_token()`。
   - 没有任何 Bearer/JWT 校验代码。
2. **密钥默认值**
   - [config.py](file:///f:/software_self/华为开发/hardware-aiLiYun/psychology-server/app/core/config.py#L21-L26)：`query_api_key: str = "change-me-query-key"`，`research_salt: str = "change-me-research-salt"`。
   - 生产实测：`GET /api/v1/devices` 不带密钥 → 401；带 `change-me-query-key` → **200**。`GET /api/v1/research/sessions` 同样 → **200**。说明生产未覆盖默认密钥。
3. **用户/账号表**
   - 生产 SQLite 共 12 张表（见 §5），**没有** `users`、`accounts`、`user`、`auth`、`token` 等表。
   - `sessions.user_id`、`sessions.external_user_id`、`device_connections.user_id` 均只是 `String(64)`，无外键、无用户表可关联。
4. **课题组 / 项目级权限**
   - 全代码无 `project`、`group`、`team`、`tenant`、`permission`、`role` 等模型或过滤条件。
   - 任何持有 `X-Api-Key` 的调用方可以读取全部设备、全部会话、全部科研导出。
5. **Flutter 侧的用户身份**
   - 主站登录在**另一台服务器**：`http://39.107.61.92:8090/api/`（[api_hosts.dart](file:///F:/development/ai_psychology_1/lib/http/api_hosts.dart#L14-L18)）。
   - `POST login` → `TokenModel`（[api.dart](file:///F:/development/ai_psychology_1/lib/services/api.dart#L277-L295)）；token 存 `SP_ACCESS_TOKEN`，由 `TokenInterceptor` 注入 `Authorization: Bearer <token>`（[cookie_interceptor.dart](file:///F:/development/ai_psychology_1/lib/http/cookie_interceptor.dart#L12-L28)）。
   - 该 JWT **只用于主站/部分 AI 接口**，psychology-server 不认识它。
   - 表情云使用独立 Dio，**不挂 token 拦截器**，只注入 `X-Api-Key`（[emotion_dio.dart](file:///F:/development/ai_psychology_1/lib/http/emotion_dio.dart#L5-L57)）。

**影响**：科研版要做「课题组账号只能操作有权访问的科研项目」，现有机制无法支撑；必须新增账号/成员/项目权限，或复用主站 JWT 做跨服务鉴权。

### 2.4 S1 / N1 会话接口

**结论：已有完整 S1 会话与 N1 外部会话号机制。**

- `sessions.session_id`：S1，服务端生成，唯一。
- `sessions.external_session_id`：N1，调用方传入，**不唯一**，同一 N1 可关联多个 S1。
- `sessions.client_request_id`：创建幂等键，与 `source_system` 组成唯一约束 `uq_sessions_source_request`。
- `sessions.source_system`：`xin_tan_tan` / `standalone` / `custom`；`custom` 客户端提交会被 403 拒绝。
- `sessions.anchor_utc_at`：相对时间原点；`timeline_events.relative_seconds` 与 `emotion_records.relative_seconds` 共用该原点。
- 创建前置：设备必须在线（30 秒内有心跳），否则 409。
- 手机端创建方式：先 `POST /devices/{id}/connect` 拿 `connection_id`，再放入 `POST /sessions` 请求体；设备端可直接带设备 token。
- 创建/查询/状态/绑定接口见 §3.3。

**与科研链路的关系**：S1 可以作为「实验会话」的天然主键，但**没有** `participant_id` / `project_id` / `group_id` / `assessment_id` 字段，无法直接关联被试档案。

### 2.8 数据库表结构与关联关系

详见 §5。要点：

- 生产共 **12 张业务表**，全部来自 `app/models`。

- 服务端只接受 `status ∈ {running, completed, aborted}`（[session.py](file:///f:/software_self/华为开发/hardware-aiLiYun/psychology-server/app/schemas/session.py#L109-L112)）。

## 5. 差距分析

目标链路：

```
科研项目 → 被试 → 实验会话 → 测评记录 → AI 对话 → 表情数据
```

### 5.1 缺失的表

| 缺失表 | 作用 | 现状 |
|---|---|---|
| `research_projects` | 科研项目（项目名、负责人、状态、时间） | 无 |
| `research_groups` | 项目下的实验组/对照组 | 无 |
| `participants` | 云端被试档案（云端 ID、项目内编号、组别、人口学、状态） | 无；仅本地 JSON |
| `accounts` / `project_members` | 课题组账号与项目访问权限 | 无 |
| `assessments` | 一次测评记录，独立 `assessment_id` | 无；目前用 `session_id + questionnaire_code + result_version` 近似 |
| `assessment_items` / `answers` | 逐题作答（若科研需要） | 无；当前设计明确拒收答案 |
| `conversations` / `conversation_messages` | AI 对话记录 | 无；仅本地 SharedPreferences |
| `research_exports`（可选） | 异步导出任务、状态、产物、过期清理 | 无；当前同步生成 |

### 5.2 缺失的字段

## 7. 待决策问题

以下口径需要用户拍板，确定后才能进入第二阶段表设计与接口设计。

### 7.1 评估记录（assessment）口径

1. **assessment 的粒度**：一次「实验会话」= 一个 assessment，还是一次「量表提交」= 一个 assessment？
   - 若一次会话包含多个量表，`assessment_id` 应挂在量表结果上，而不是会话上。
2. **assessment_id 是否独立成表**：独立 `assessments` 表（推荐，便于按被试/量表/时间查询），还是只在 `external_result_snapshots` 上加字段？
3. **同一被试同一量表重复测评**：`result_version` 目前是「同一 S1 内同量表」的版本号；跨会话重复测评需要新的稳定标识，是否用 `assessment_id` 区分？
4. **「最新一次」的判定**：按 `created_at`、`reported_at`、`result_version` 还是会话 `ended_at`？并列时如何取？

### 7.2 项目 / 分组 / 权限

5. **权限模型**：课题组账号是复用主站 `39.107.61.92:8090` 的 JWT，还是 psychology-server 自建账号？
   - 若复用主站 JWT，需要主站提供跨服务校验或 introspection 接口。
   - 若自建，需要新增账号、密码/验证码、token 签发与刷新。
6. **项目成员角色**：项目负责人/实验员/只读访客是否需要区分？是否只做「项目可见/不可见」二值权限？
7. **数据隔离边界**：一个账号能否同时属于多个项目？跨项目查询是否允许？
8. **设备归属**：设备是否绑定项目？同一设备是否允许被多个项目使用（例如换实验室）？
9. **默认密钥处置**：生产 `change-me-query-key` 是否立即更换？科研版 APK 是否改为登录后动态获取短期凭证，而不是内置固定密钥？

### 7.3 被试档案

10. **云端被试 ID 与本地 ID 的映射**：本地 `ResearchParticipant.id` 是随机本地 ID，云端 `participant_id` 是新生成；迁移时以哪个为稳定键？
11. **项目内编号唯一性**：`participant_code` 在项目内唯一，还是全局唯一？跨项目是否允许相同 P001？
12. **重复被试判定**：同一项目下 `participant_code` 相同即视为同一人，还是需要结合姓名/学校/年级？是否允许人工合并？
13. **敏感字段**：需求要求「不上传没有必要的姓名、电话等身份信息」，但本地模型有 `name`、`phone`。云端被试表是否只保留 `code`、`gender`、`age`、`school`、`grade`、`group`、`status`？`name`/`phone` 是否只留本地？
14. **归档/恢复/删除**：归档是否影响历史数据下载？是否允许物理删除？删除后历史测评如何保留？

### 7.4 历史数据迁移

15. **本地已有 P001/P002 如何上云**：首次同步时自动创建云端被试，还是要求用户在下载中心手动「迁移」？
16. **本地测评结果如何关联云端会话**：本地结果里有 `s1_session_id`、`external_session_id`（可能为空）；为空的历史记录（纯离线测评）如何归属？是否允许「无会话的历史测评」？
17. **重复记录识别**：本地与云端都有同一被试同一量表同一时间附近的结果时，以哪边为准？是否需要 `client_request_id` / `source_payload_sha256` 去重？
18. **旧版本兼容**：本地 `research_results_*` 最多 20 条/量表，迁移前是否先扩容或全量导出备份？迁移脚本是否只读本地、不删除原数据？
19. **备份与核对**：迁移前备份形式（文件/云盘/本地副本）、核对口径（条数、总分、时间、被试编号）由谁确认？

### 7.5 AI 对话

20. **对话数据归属**：AI 对话上传到 psychology-server，还是保留在主站/AI 8089，仅在科研导出时按 `conversation_id` 关联？
21. **对话内容范围**：只存用户与 AI 的文本，还是含语音转写、评分中间结果、系统提示词？是否涉及隐私与知情同意？
22. **对话与测评的关联键**：用 `session_id`（S1）、N1，还是新建 `conversation_id`？一次会话是否可能有多段对话？

### 7.6 下载中心与格式

23. **JSON 格式**：需求写「JSON」，当前导出是 JSONL。科研版下载中心要输出单个 JSON 数组、JSONL，还是两者都提供？
24. **数据包结构**：是否严格按需求中的 `participants.csv`、`sessions.csv`、`assessments.csv`、`expression_summary.csv`、`expression_timeline.csv`、`conversation.csv`、`metadata.json`、`data_dictionary.csv` 命名？当前导出是 `raw/`、`derived/`、`meta/` 分目录 + `manifest.json`、`data_dictionary.md`。
25. **大数据量**：是否需要异步导出任务、断点续传、分页下载、过期清理？阈值是多少（会话数/行数/字节）？
26. **下载权限**：下载中心是否只允许项目成员下载本项目数据？是否需要下载审计日志？

### 7.7 其他

27. **时区**：数据库 UTC、查询参数北京时间、导出 UTC；科研版界面统一显示北京时间还是跟随设备时区？
28. **离线补传**：被试档案同步的冲突解决策略（本地优先/云端优先/字段级合并/人工选择）？
29. **手机版隔离**：新增接口是否全部挂在 `/api/v1/research/*` 或新前缀，避免影响手机版现有路径？是否需要对手机版隐藏科研接口？

## 9. 本轮结论

1. 现有 psychology-server 是一个**单租户、以会话为中心**的采集与导出服务：会话、设备、时间线、表情、量表聚合结果、导出链路完整，但没有账号、被试、项目、分组、测评、对话这些科研管理实体。
2. 「科研项目 → 被试 → 实验会话 → 测评记录 → AI 对话 → 表情数据」中，**只有「实验会话 → 表情数据」和「实验会话 → 量表聚合结果」是通的**；被试、项目、分组、AI 对话四段在云端缺失。
3. 量表结果**只写不读**；逐题作答与答案值按现有设计不入库。
4. 导出能力可作为科研数据包的底座，但当前只支持会话/时间/数据类型筛选，**不支持按被试、项目、组别、量表、最新一次筛选**，且为同步 zip、JSONL 而非 JSON 数组。
5. 生产默认 `X-Api-Key` 可用是上线前必须修复的 P0 安全问题；在修复前不应把科研版下载中心接到现有 `/research/*` 接口。
6. 存在一处已确认的接口契约不一致：Flutter 发送 `interrupted`，服务端只接受 `aborted`，导致中断会话状态不落库；科研版需要「已完成/已中断/异常」口径时必须先修复。

> 本轮仅完成审计，不包含表设计、接口设计与代码实现。进入第二阶段前，请先确认 §7 的待决策问题，尤其是 assessment 粒度、权限模型、被试字段范围、历史数据迁移规则与 AI 对话归属。
