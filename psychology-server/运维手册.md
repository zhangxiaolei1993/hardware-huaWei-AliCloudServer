> 面向服务器管理者。项目部署目录：`/opt/psychology-server`
> 服务器公网 IP：`8.140.240.43`

---

## 一、这个项目做了什么

一个支持多种设备的**心理测评云平台后端**，第一阶段只做「表情识别」。

**架构（三层）**：

```text
通用设备管理(Device) → 通用会话管理(Session) → 表情业务(Emotion)
```

- Device、Session 是通用的，以后接任何设备都复用
- 每种设备业务用各自独立的接口和数据表，**没有万能数据接口**
- 开发板只负责采集和识别；**最终统计结果一律由服务器重新计算**

**当前对接设备**：华为 Atlas 200I DK A2（Ascend 310B4）+ 摄像头，做表情识别。

**明确还没做（第二阶段）**：心率、EEG、眼动、实时流、WebSocket/MQTT、Nginx/HTTPS、Docker。

---

## 二、服务是怎么跑的

- 用 **systemd** 托管，服务名 `psychology-server`
- 已设置：**开机自动启动 + 崩溃后 5 秒自动重启**
- 监听端口：`8000`
- 所以正常情况下**你不需要手动启动服务**，重启服务器也会自己起来

常用控制命令（SSH 登录后任意位置执行）：

| 操作 | 命令 |
| --- | --- |
| 查看状态 | `systemctl status psychology-server` |
| 启动 | `systemctl start psychology-server` |
| 停止 | `systemctl stop psychology-server` |
| 重启 | `systemctl restart psychology-server` |
| 查看是否开机自启 | `systemctl is-enabled psychology-server` |

## 三、怎么看日志（重点）

### 1. 实时看日志（最常用）

```bash
journalctl -u psychology-server -f
```

屏幕会停住，设备一有动作就实时滚动。**退出按 `Ctrl + C`**，这只是不看了，**不会停止服务器**。

### 2. 看最近 N 行（不实时）

```bash
journalctl -u psychology-server -n 100 --no-pager
```

### 3. 看应用自己的日志文件

```bash
tail -f /opt/psychology-server/logs/app.log
```

（journalctl 信息最全，含启动报错；app.log 只看业务，更清爽）

### 4. 用 tmux 挂一个看日志的窗口（关掉 SSH 也保留）

```bash
tmux new -s logs                              # 新建窗口
journalctl -u psychology-server -f            # 进去后看日志
# 按 Ctrl+b，松开，再按 d  →  挂到后台
tmux attach -t logs                           # 下次回来看
tmux ls                                       # 查看所有窗口
```

### 5. 日志里每一行代表什么

| 日志内容 | 含义 |
| --- | --- |
| `device xxx registered` | 有设备注册成功 |
| `heartbeat from xxx ...` | 设备心跳，说明**设备在线连着**（约每 30 秒一条） |
| `session xxx created by device ...` | 设备发起了一次测评 |
| `emotion data uploaded ... dominant=xxx` | 测评数据上传完成，括号里是主导表情 |
| `http error ... 401` | 认证失败（token 缺失或错误） |
| `http error ... 404` | 设备/会话不存在 |
| `http error ... 422` | 数据非法（表情不对、置信度越界、timeline 为空） |
| `http error ... 409` | 会话已完成，拒绝重复上传 |

> 判断设备在不在线：看有没有持续的 heartbeat；超过 30 秒没心跳会被记为 offline。

## 五、API 列表

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/v1/health` | 健康检查 |
| POST | `/api/v1/devices/register` | 注册设备，返回 token |
| GET | `/api/v1/devices/{device_id}` | 查询设备（自动判断在线状态） |
| POST | `/api/v1/devices/{device_id}/heartbeat` | 心跳（Atlas 调用，需设备 token） |
| POST | `/api/v1/devices/{device_id}/connect` | **手机连接设备**（手机调用，不需设备 token） |
| POST | `/api/v1/devices/{device_id}/disconnect` | **手机断开设备**（手机调用） |
| POST | `/api/v1/sessions` | 创建测评会话 |
| GET | `/api/v1/sessions/{session_id}` | 查询会话 |
| POST | `/api/v1/sessions/{session_id}/status` | 更新状态 running/completed |
| POST | `/api/v1/emotion/sessions/{session_id}/data` | 批量上传表情 timeline |
| GET | `/api/v1/emotion/sessions/{session_id}/result` | 获取服务器计算的结果 |

**设备认证**：除注册和健康检查外，请求头要带：

```text
X-Device-Id: 设备ID
X-Device-Token: 注册时返回的 token
```

## 六、手机 App 连接与在线检测流程

```text
1. 手机输入/扫码得到 device_id，点"连接设备"
2. 调 POST /devices/{device_id}/connect，body: {"app_client_id":"手机UUID"}
     ├─ 404               → 提示"未找到设备"
     ├─ connected=false   → 提示"设备离线"
     └─ connected=true    → 显示"✅ 已连接"，保存 connection_id
3. 设备页每约 10 秒轮询 GET /devices/{device_id}，按 status 刷新"已连接/已断开"
4. 退出设备页 → 调 POST /devices/{device_id}/disconnect（带 connection_id）
```

- 手机接口**不需要设备 token**，`app_client_id` 由手机首次安装时生成并保持不变
- 同一手机重复点连接是幂等的，返回同一 connection_id
- Atlas 断网后，最长 30 秒（心跳超时）手机会看到 offline

## 七、设备（Atlas）一次完整使用流程

```text
1. 设备开机 → 调 register 注册，保存返回的 token（只需一次，重复注册幂等）
2. 每约 30 秒 → 调一次 heartbeat（贯穿全程，服务器据此判断在线）
3. 测评开始 → 调 POST /sessions，拿到 session_id
4. 设备本地：摄像头采集 → 人脸检测 → NPU 推理 → 记录 timeline
5. 测评结束 → 调 emotion/data 一次性批量上传（client_request_id 用一个 UUID）
6. App/Flutter → 调 emotion/result 获取服务器算好的结果
```

完整 curl 示例见 [README.md](README.md)，也可在 `/docs` 页面直接点「Try it out」调试。

## 八、表情识别规则

- **合法表情 8 类**：neutral、happiness、surprise、sadness、anger、disgust、fear、contempt
- **confidence（置信度）必须在 0~1**
- timeline 不能为空
- **时长算法**：相邻两条记录的时间差归前一条的表情。
  例：`0.5 neutral / 1.0 neutral / 1.5 happiness` → neutral 0.5 秒、happiness 计到下一条
- **服务器重算**：每种表情时长与百分比、主导表情、平均置信度、人脸覆盖率
  （face coverage 用 `检测到人脸的帧数 / 总帧数` 重算，不采用开发板给的值）
- **防重复**：`(session_id, client_request_id)` 唯一；网络重试不会重复插入数据
- 会话已完成后默认禁止再次上传（返回 409）

## 九、数据存在哪

- 第一阶段数据库：**SQLite**，文件 `/opt/psychology-server/psychology.db`
- 全部通过 SQLAlchemy 访问；以后换 MySQL 只需改 `.env` 的 `DATABASE_URL`

4 张表：

| 表 | 作用 |
| --- | --- |
| `devices` | 设备信息、能力、token |
| `sessions` | 测评会话 |
| `emotion_records` | **原始 timeline（必须保留原始时间序列）** |
| `emotion_results` | 服务器计算结果 |

## 十、常见问题排查

**1. 网页打不开 / 接口超时**

- 查服务：`systemctl status psychology-server`（不是 active 就 `systemctl restart`）
- 查端口：`ss -tlnp | grep 8000`
- 阿里云控制台确认**安全组放行了 8000 端口（TCP，来源 0.0.0.0/0）**

**2. 设备一直显示离线**

- 设备是否在持续发 heartbeat
- token 是否正确（错误会报 401）

**3. 日志提示 409**

- 该会话已上传完成，不允许重复传；如果是设备重试，应使用**同一个 client_request_id**，服务器会幂等返回

**4. 启动报 address already in use**

- 8000 被占用：`ss -tlnp | grep 8000` 找到占用进程处理
